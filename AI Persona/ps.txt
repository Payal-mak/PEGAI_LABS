AI Persona Web Application using Gemini API 
1. Objective 
Develop a web-based AI Persona Application using the Gemini API. 
The application should allow users to interact with different AI personas and receive responses according to the selected persona's role, audience, context, format, constraints, and language. 
The main focus of this deliverable is: 
Frontend Development + Gemini API + Persona Prompt Engineering + Multiple Persona Responses 
2. Important Instructions 
● Minimum 4 personas are required. 
● The user must be able to select one or multiple personas. 
● Responses must be generated using the Gemini API. 
● Different personas should provide meaningfully different perspectives. ● For multiple personas, prefer one Gemini API request containing all selected personas rather than making unnecessary separate requests. 
● Use the six Prompt Card elements: 
○ Role 
○ Audience 
○ Context 
○ Format 
○ Constraints 
○ Language 
● The application must be contained in one HTML file containing HTML, CSS and JavaScript. 
● Do not publish your actual Gemini API key on GitHub. 
● The application must handle basic input/API errors. 
● The submitted application must be functional and demonstrated in the video. ● Your GitHub repository must contain a clear README. 
● Deliverables are: Demo video link of your project and Github link with no api key

4. User Interaction 
The application must allow the user to: 
A. Ask One Persona: The user selects one persona and enters a question. Example: 
"I know Python and basic Machine Learning. What should I learn to become an AI Engineer?" 
The selected persona should provide the response according to its defined persona. Questions other than the persona should say I don’t know. 
B. Ask Multiple Personas: The user must also be able to select multiple personas and ask the same question. 
Example:

The application should then generate a separate response from each selected persona.

6. Persona Prompt Card 
Every persona must be designed using the following six Prompt Card elements:These six components should be used to construct your persona prompt. 
Prompt Card Element 
Meaning
Role 
Who should the AI act as? What persona should it adopt?
Audience 
Who is the AI giving the response to?
Context 
What background information should the AI consider?
Format 
How should the AI present its response?
Constraints 
What rules or limitations should the AI follow?
Language 
Which language should the AI use?



7. Prompt Card Example 
For example, we are celebrating National Space Day and have already prepared a poster. We want to upload it on our Instagram account. To generate an appropriate caption, we can create a Prompt Card using the six elements. 
Sample Prompt Card 
Prompt Card Element Example 
Role Social Media Manager 
Audience University/college students 
Context We are celebrating National Space Day and have already designed an Instagram poster for the occasion. Write a
caption to accompany the poster and celebrate India's 
achievements in space with ISRO. 
Format Instagram caption + hashtags 
Constraints Under 25 words, simple and engaging, no emojis, no jargon 
Language Simple English, no hard vocabulary 
The complete Prompt Card can therefore be written as: 
Role: Social Media Manager 
Audience: University/college students 
Context: We are celebrating National Space Day and have already designed an Instagram poster for the occasion. Write a caption to accompany the poster and celebrate India's achievements in space with ISRO. 
Format: Instagram caption + hashtags 
Constraints: Under 25 words, simple and engaging, no emojis, no jargon Language: English 
Important 
This example is only to explain how to create a Prompt Card.

15. Gemini API 
The actual AI-generated responses must come from the Gemini API. 
Do not use hard-coded responses such as: 
JavaScript 
if (persona === "Technical") { 
 response = "Learn Python and Machine Learning."; 
} 
The response must be generated by Gemini based on the prompt. 
16. API Key Security 
Never submit or publish your actual Gemini API key in a public GitHub repository. Do not expose your API key in the submitted source code. 
Do not commit: 
None 
.env 
or any file containing your actual API key. 
If a temporary key is used for demonstration, remove it before uploading the project to a public repository.
17. Error Handling 
Your application should handle basic situations such as: 
No persona selected 
Display: 
Please select at least one persona. 
Empty question 
Display: 
Please enter your career-related question. 
API error 
Display an appropriate message instead of allowing the application to crash.
